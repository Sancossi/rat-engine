# Контекст BMad: Rat Expedition

Это обязательная проектная адаптация upstream workflows, а не вторая система
управления задачами. `AGENTS.md` и указания пользователя имеют приоритет.

## Принятый замысел и границы

Читать `docs/rat-expedition-preproduction-plan.md` и текущую карточку. Пользователь
уже утвердил малую одиночную RPG на 1–2 часа для Windows: до трёх разумных крыс,
магическая реликвия, мрачное средневековое фэнтези, исследование связанных мест,
системные взаимодействия, диалоги с последствиями, меню пошагового боя без сетки,
2D-персонажи в 3D-мире. Один разработчик с ИИ, несколько часов в день, минимум денег.
Не повторять закрытое интервью. Новые авторские детали обозначать как предложения
или гипотезы прототипа. Выбор движка остаётся последующим решением.

## Единственные источники и маршруты

| Артефакт | Канонический путь |
|---|---|
| GDD | `vault/game/GDD.md` (сохранять этот регистр имени) |
| Концепция, нарратив, художественное направление | `vault/game/expedition/` |
| Этапы и сводные эпики | `vault/production/roadmap/` |
| Решения и смена концепции (native decision-log) | `vault/production/decisions/`, по ссылке из GDD |
| Исполнимые задачи и баги | `vault/production/tasks/`, `vault/production/bugs/` |
| Спринты и их статусы | `vault/production/sprints/`, `vault/production/Task board.base` |
| Архитектура, сравнение движков, технические проверки | `docs/` |
| Native sprint-status.yaml | `docs/bmad/generated/sprint-status.yaml`, только производная копия |

Пути этой таблицы заменяют стандартные dated GDD folders, standalone `epics.md`,
`decision-log.md`, `story.md`, технические документы внутри planning_artifacts и native output paths.
Не создавать вторые GDD, story-файлы и вручную редактируемый sprint-status.
`gds-create-epics-and-stories` создаёт roadmap и карточки через шаблоны vault;
`gds-create-story` уточняет существующую карточку. Дедупликация через `rg` обязательна.
Новая Markdown-заметка в vault содержит `type` и остальные обязательные scalar
frontmatter поля; wikilinks используют реальное имя файла. Историю не переписывать.

## Перед использованием production workflows

Запустить `python scripts/bmad_vault.py sync` и затем `check`.
`gds-sprint-planning` работает с каноническими карточками и вызывает адаптер вместо
собственного YAML writer; `gds-sprint-status` читает производную проекцию. В проекции
ключ карточки разрешается через `card_paths`; не искать или создавать одноимённый
standalone story. Generated IDs могут меняться после вставки карточки; постоянная
идентичность для ссылок, зависимостей и pickup — canonical path из `card_paths`.
Это адаптированный протокол, не неизменённый native story reader.
`vault_metadata` сохраняет различия blocked/archived/wont-fix, отдельный bug review
и исходные статусы. `backlog` не означает готовность к работе. `ready-for-dev` не
выдаётся автоматически: зависимости и приёмку проверяет ведущий агент по карточке.
При отсутствии активного спринта проекция пустая: не запускать native validate,
требующий хотя бы одну story; сообщить, что активного спринта нет.

Любые native инструкции изменить YAML статус заменяются изменением канонической
карточки ведущим агентом и повторной генерацией. Исполнитель не меняет статусы и
не закрывает карточку. Баг остаётся `Investigating` во время ревью с отдельным
`review: In review`; отрицательное ревью останавливает pickup. Только ведущий агент
принимает результат независимого read-only reviewer. Один исполнитель пишет.
Несколько независимых read-only проверок могут выполняться параллельно.

Для документационного этапа не запускать прототипирование, не создавать тесты C++
и не открывать игровую разработку из-за native автоматического next-action.
Проверки: vault checker, Python adapter tests, документальный trace design → task →
review; финальная Release-сборка редактора выполняется ведущим агентом при закрытии.
Отчёты различают static discovery, загрузку skill/resolver, ручное ревью и GUI-тест.

## Загрузка и совместимость

Общаться и писать по-русски. Использовать реальные `.agents/skills/gds-*/SKILL.md`,
а не старые README-алиасы `bmgd-*`. Полный upstream pack установлен; включённая
поддержка движка не означает его выбор. Core 6.12.0 упаковывает editorial passes
в `bmad-review`: если brief ссылается на отсутствующий старый editorial skill,
использовать structure/prose review из установленного `bmad-review`, явно указав
адаптацию в evidence. Не утверждать, что отсутствующий skill запускался.
