# P1.1 — первая самостоятельная сцена Stride

Дата: 2026-09-09. Исполнимый срез существующей [карточки P1](../vault/production/tasks/expedition-prototype-traversal.md); [архитектура](rat-expedition-architecture.md), [полный P1](rat-expedition-traversal-spec.md). Статусы только в vault. Результат — одна играемая плоская сцена и проверенный Windows ZIP; мост/лаз/лестница/спутники/переходы/MCP остаются следующими срезами.

## Реализация

1. В `games/rat-expedition/` создать Core, Windows executable и Core.Tests по архитектуре. SDK 10.0.300, TFM приложения `net10.0-windows`, RID `win-x64`, Direct3D11. `Stride.Engine` и build-only `Stride.AssetCompiler` имеют точную NuGet версию `[4.4.0-dev]` из закреплённой исходной основы. AssetCompiler: `IncludeAssets="build;buildTransitive"`; shader/content compilation нужна даже code-first сцене. Не подменять её ручным копированием DLL. Source mapping: `Stride.*` local feed, более точный `Stride.Dependencies.*` NuGet. Относительный local feed в game NuGet.Config — `../../../stride/bin/packages`; с другим checkout build передаёт фактический путь. Зафиксировать package locks после успешного restore.
2. В `Content/courtyard.json` версии 1 задать id, прямоугольный floor, spawn XYZ и несколько стен с устойчивыми ids/min/max. Из одних данных построить видимые коробки и Core ограничения: конечные числа, min<max, spawn внутри пола и вне стен с radius 0,2. В `Content/sprites/rat.png` скопировать существующий оригинальный 64×192 atlas, в `tools/rat_sprite.py` его источник с обновлённым output. Исходные dirty файлы не менять/стейджить. `Content/credits.json` указывает новое размещение, происхождение/условия; при использовании Noto Sans включить OFL.
3. Windows `Game.LoadContent` создаёт Scene/SceneInstance, фиксированную камеру 3/4 (`CameraProjectionMode.Orthographic`, `OrthographicSize`), compositor `GraphicsCompositorHelper.CreateDefault(false, camera: ...)`, пол/стены через `CubeProceduralModel.Generate(Services)` и простой материал/свет. Никакого свободного вращения камеры. PNG реально читается от `AppContext.BaseDirectory`, foot anchor совпадает с motor position, один atlas frame или простая ходьба отображается через SpriteComponent/provider. Проверка обнаружила, что полный camera billboard наклоняет голову в переднюю стену: выбран upright Sprite с yaw 45°, PixelsPerUnit 60, PointClamp, IgnoreDepth=false и PremultipliedAlpha=false. Проекция полуширины .188 units помещается в footprint radius .2; герой перед стеной виден целиком, за ней перекрывается глубиной.
4. Core motor на плоскости XZ: WASD camera-relative, скорость 3 units/s, нормировка диагонали, radius 0,2; floor bounds и стены учитывают footprint, движение вдоль стены возможно, длинный dt не переносит сквозь неё. Fixed tick 1/120 с и ограниченный catch-up. Одна позиция истины, renderer лишь применяет snapshot. При focus loss ввод/accumulator сбрасываются. Никакого обещания многоуровневой физики этой реализацией.
5. Добавить `scripts/stride/build-game.ps1`: проверить engine lock/HEAD/feed, restore/build, Core tests, self-contained Release publish в `build/stride-game/<timestamp>/publish/`, ZIP рядом `rat-expedition-0.1.0-win-x64.zip`. Timestamp сохраняет предыдущие артефакты. `PublishAot=false`, `PublishTrimmed=false`, `PublishSingleFile=false`; включить полный publish с `data/` shader database, native/runtime libraries, raw Content, credits/лицензиями. GameStudio/upstream source не меняются. Компиляция эффектов локальная, remote effect compiler отключён. Чистые core tests не требуют GPU; команда должна возвращать ненулевой код при провале.
6. Добавить минимальные параметры диагностики: размер окна, каталог evidence, ограниченный сценарий/число кадров и load-failure режим/путь контента. Автоматический маршрут подаёт команды через тот же input→motor путь, не подменяет позицию для доказательства стен. Capture реального backbuffer в EndDraw до base.EndDraw; пригодный API — `BackBuffer.Save(GraphicsContext.CommandList, stream, ImageFileType.Png)`. Журнал включает source SHA, game commit, package versions, размер, backend/реальный adapter, позицию/результат и ошибки. Файлы пишутся в заданный evidence dir. Диагностический запуск не выдаётся за ручной плейтест.

## Приёмка

- Given готовая pinned основа, when build-game выполнен, then build/test/publish/ZIP проходят и manifest показывает фактические зависимости, SDK, HEAD и пути. Нужные first-party пакеты отсутствуют → явный отказ без stable fallback.
- Given обычный/диагональный/упирающийся в стену ввод, when fixed steps выполнены, then скорость нормирована, footprint остаётся на полу и вне стен; движение вдоль стены работает. Core tests проверяют эти наблюдаемые случаи, некорректный spawn/bounds/числа и отсутствие скачка после focus loss.
- Given отдельная копия publish, when PNG или JSON отсутствует/повреждён, then читаемая причина и ненулевой exit, без тихой подстановки квадрата. Проверить реальный executable, не только JSON validator.
- Given ZIP извлечён вне source checkout, when executable запущен с другим cwd, then сцена/PNG/shaders работают без editor/SDK/source/network. Полный publish нужен: само наличие exe не закрывает приёмку. Проверка на текущем ПК не утверждает тест на чистой машине; явно записать эту границу.
- Given реальное GPU окно 1280×720 и 1920×1080, when маршрут исполняется, then видны двор/PNG, WASD соответствуют экрану, стены ограничивают движение, прозрачность/depth правильны. Сохранить PNG каждого размера и журнал фактического adapter. При невозможности GPU capture зафиксировать блокер; headless тесты его не заменяют.

Native-resolution rendering допустим для этого среза; масштаб/640×360/движение без мерцания остаются A7 проверками полного P1. Не объявлять всю карточку P1 завершённой. Evidence — `docs/audits/2026-09-09-stride-first-game-slice.md`; тяжёлые artifacts под `build/stride-game/`. Независимый reviewer проверяет Core/loader/package paths и отличает реальные кадры от headless evidence.
