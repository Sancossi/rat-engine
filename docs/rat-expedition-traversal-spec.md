# P1 — маршрут крысы на собственном движке

Дата: 2026-09-08. Specification для [существующей карточки P1](../vault/production/tasks/expedition-prototype-traversal.md); [архитектура](rat-expedition-architecture.md), [ADR-017](../vault/production/decisions/ADR-017%20Rat%20expedition%20uses%20rat-engine.md), [GDD A4/A7](../vault/game/GDD.md). Это будущая реализация после закрытия E1 и включения P1 в спринт. Настоящий документ не разрешает pickup сам по себе.

## Результат и порядок срезов внутри P1

Сначала самостоятельный `rat-game` и один дисковый PNG в сером дворе; затем ввод/лаз/лестница; затем вторая площадка, переходы, спутники и полный приёмочный проход. Каждый срез коммитится после относящихся к нему проверок. Всё остаётся одной карточкой P1, без параллельной BMad story-очереди.

Две новые карты: `data/expedition/maps/courtyard.json` и `sluice.json`, ids `expedition_courtyard`/`expedition_sluice`. Использовать существующий JSON map format/loader, не менять старые карты и не переносить их события. Первая площадка примерно 16×12 клеток: обычный обход, прямой низкий проход (ровный пол, без лестницы внутри), лестница к площадке высотой 1,6 world units с безопасными выходами, стена перед камерой, обозначенный край для проверки восстановления и портал в водосброс. Вторая примерно 8×8: место появления вне портала, обратный портал и ровный безопасный маршрут. Размеры — параметры fixture, не новая квота контента.

Одна единица мира принимается за длину тела лидера. Ходьба 3 units/s, приседание 1,5, подъём 1; WASD относительно фиксированной камеры, E/Enter контекст, удержание Ctrl стойка, Escape пауза. Свободный прыжок и вращение камеры в игре отключены. Два спутника — различимые варианты временного спрайта, без физических препятствий.

Уточнение по двум референсам 2026-09-08: внутри первой площадки разместить один короткий мост и независимый проход под ним при одинаковых XZ, с доступом наверх по существующему ramp collider. Предложенные A4 размеры: верх 1,6, толщина 0,2, низ 1,4 units; для Standing 0,8 остаётся запас. Это отдельный высокий проход, не замена низкого лаза с потолком 0,6. Опоры/перила не перекрывают нижний маршрут. Использовать существующие floor slabs/occupancy; не поднимать ground column до верха моста. Ступенчатый вид марша — будущий E3 visual поверх согласованного пандуса. План площадки можно локально расширить ради безопасных подходов, без второй большой карты или дополнительных механик.

## Минимальные интерфейсы и данные

В `src/game/expedition/` ввести `ExpeditionSession`, `TraversalInput`, `TraversalSnapshot` и загрузчик сцен. `TraversalInput` содержит экранные оси, `crouch_held`, одноразовые `interact_pressed`/`pause_pressed`. `tick(input)` потребляет фиксированный dt 1/120 с; snapshot содержит scene id, координаты/стойку лидера, три позиции представления, режим и одну контекстную подсказку. Графические и файловые handles не входят в эти типы. Окно/frame accumulator остаются в `apps/game/`.

`data/expedition/project.json` версии 1 задаёт start scene `expedition_courtyard` и словарь scene id → путь metadata. Файлы `scenes/courtyard.json`, `scenes/sluice.json` версии 1 содержат:

| Поле | Контракт P1 |
| --- | --- |
| `scene_id`, `map` | Уникальный id; путь map относительно `data/expedition/`, id карты должен совпадать |
| `spawns` | Словарь стабильное имя → конечные x/y/z; обязательный `entry`; координаты на свободной устойчивой поверхности |
| `portals` | Список id, XZ bounds и `feet_y_min`/`feet_y_max`, target scene, target spawn; переход только по новому E/Enter внутри 3D области ног и без разделяющей преграды |
| `low_passages` | Список id, XZ bounds, `floor_y`, `ceiling_y`; прямоугольный ровный проход; ceiling-floor между 0,4 и 0,8 units |
| `recovery_y` | Порог падения ниже безопасного пола; в fixtures -2 units |
| `occluder_groups` | Стабильный id группы и members: `blocker`/`floor_slab` с исходным индексом либо `voxel` с координатами occupancy cell; привязка к соответствующим draw ranges. Только представление; проверять существование, уникальность и отсутствие членства в двух группах |

У всех чисел проверять конечность, bounds min<max, floor<ceiling; все referenced scene/spawn существуют, пути относительные внутри каталога данных без `..`/абсолютных путей. Сначала загрузить и проверить проект и metadata обеих сцен. Формат новых метаданных изолирован от старого map format; не добавлять непонятные поля в старый loader. Геометрия и metadata fixtures согласуются тестом (spawn/порталы свободны, низкий проход ровный, его потолок виден). Нет динамической загрузки произвольного пути из текста события.

Диапазоны portal feet Y проверять на конечность и min<max. Для контекстных лестниц учитывать фактический нижний/верхний вход существующего motor и свободный подход к нему; ближайшая по XZ лестница на другом уровне не допустима. Сначала исключить цель вне её области высоты/за твёрдой преградой, только затем nearest/id. Рампы допускают непрерывную высоту: фиксированные индексы этажей не заменяют геометрию. В P2 такой же порядок применить к предметам; исходный `EventRuntime` уже имеет height filtering, но новые игровые цели должны доказать его эквивалент отдельно.

## Стойка, лестница и смена сцены

Существующий `PlayerBody` не имеет высоты/стойки; `CollisionBody` имеет height, но `collision_body_from_player` выставляет константу 1,6. В P1 добавить `PlayerBody::height` с legacy default 1,6 и передавать его во все cylinder/ceiling/wall/ladder probes вместо констант. Добавить в `SimulationConfig` отключённую по умолчанию posture policy с высотами Standing/Crouched и скоростями walk/crouch/climb; ExpeditionSession включает её с высотами 0,8/0,4, скоростями 3/1,5/1 и radius 0,2. `InputButtons`/`InputFrame` получают `crouch_held`; игровой GLFW adapter связывает Ctrl, editor не включает policy. В `SimulationSession::tick` policy выбирает фактическую высоту/скорость до моторного шага; snapshot выводит стойку из принятой высоты тела.

Низкий проход строится **настоящими floor slabs/solid geometry** с нижней гранью потолка на 0,6 units над полом и боковыми стенами. Metadata описывает место и подсказку, не заменяет физическую коллизию. Стоя невозможно войти даже диагонально; присев можно. При попытке встать проверять полный цилиндр увеличенной высоты против потолка/стен, не единственный луч или центр. Высота участвует в горизонтальном sweep/substeps, вертикальном ограничении и проверке выхода с лестницы; сохранять прежний default остальных callers. Нельзя отключать collision у потолка или откатывать только изображение после прохода сквозь него.

Совместимость входит в P1: `replay.cpp` сейчас строго перечисляет поля PlayerBody/InputFrame/SimulationConfig и checksum. Обновить dump/load/validation/checksum для новых полей, поднять replay schema/runtime/checksum с 2 до 3; старые replay возвращают `Incompatible` с предложением перезаписи, без автоматического преобразования. Старые fixtures сохранить как negative compatibility cases, новые записать отдельно. Обновить debug snapshot, input bindings и headless replay tests: crouch → blocked stand → exit воспроизводится с одинаковым checksum; неизвестные/невалидные высоты и policy отклоняются. `GameState` save schema 2 и старые maps не менять: игровые слоты появятся в P5, editor posture policy выключена. Полный межсценовый replay экспедиции не обещается существующим однокартовым replay: переходы проверяются отдельным game-level headless сценарием.

При отпускании Ctrl под потолком остаться присевшим с подсказкой «Здесь нельзя встать»; после выхода полным footprint автоматически встать. Не разрешать смену стойки на лестнице: перед захватом требуется возможность стоять, во время подъёма Ctrl игнорируется. Переиспользовать текущий climb motor и проверку выхода; E включает контекст лестницы. Скорость задаётся posture policy: существующий climb motor использует `PlayerBody::speed`, на climbing ticks установить 1 и восстановить walk/crouch после выхода. Вверх/вниз по WASD, выходы не выбрасывают в blocker или пустоту. Отдельный новый climb controller не нужен.

Портал по E подготавливает кандидат `SimulationSession`; кандидат и активная сессия принадлежат `unique_ptr`, замена выполняется swap. Успешная загрузка устанавливает target spawn, Standing, grounded jump state, очищает accumulator/pending input и след спутников, затем подменяет активную сцену. Прогресс P1 отсутствует; будущие игровые данные не должны теряться при этой границе. Ошибка загрузки/валидации оставляет старую сцену и позицию. В обоих направлениях spawn вне portal bounds, следующая активация требует отпускания и нового нажатия E. При падении ниже recovery_y возвращать к последней grounded/не-climbing позиции текущей сцены, пригодной для Standing; сбросить скорость/ввод/спутников. После перехода такой точкой становится новый spawn.

Пауза полностью останавливает игровые ticks, сбрасывает accumulator и `clear_pending_input`; клавиши меню не поступают в мир. При resume требуется новое нажатие E/Enter; WASD, уже удерживаемые при закрытии паузы, могут возобновить движение, но одноразовое действие не повторяется. Потеря фокуса ставит на паузу. При ladder/portal overlap показывать ближайшую допустимую цель, ничью решает стабильный id; одно нажатие обслуживает только эту цель.

## Картинка и ресурсы

Новый `SpriteRenderer` в графической части `rat_engine` загружает RGBA PNG через уже доступный закреплённый `bimg_decode` (приватная линковка графического target) и владеет bgfx texture/program/buffers; освобождение до shutdown renderer. Временный atlas `sprites/rat.png`: клетки 32×48, четыре строки направлений, два кадра в строке; один atlas с разной tint для трёх героев. Показ stance/climb можно получить уменьшением высоты изображения/выбором этих кадров; финальная анимация E3 здесь не нужна. Файл реально читается с диска, заглушка цветным квадом не закрывает sprite acceptance.

Камера фиксирована 3/4 на сцену, без динамического climb-turn. Feet anchor спрайта совпадает с телом, quad обращён к камере. Окружение рисует `GreyboxScene`; добавить режим без старой фигуры player, сохранив прежний default редактора. PNG alpha cutout (discard alpha<0,5), depth test/write, nearest filtering; полупрозрачное сортирование не нужно. Sprite draw использует те же матрицы/глубину, что геометрия.

Рендерить сцену во внутренний target 640×360 и увеличивать nearest целым масштабом (2× для 1280×720, 3× для 1920×1080); UI рисовать в native resolution. Остальные размеры — целый fit с letterbox, минимум окна 640×360. Снапить только отображаемый feet anchor к пикселю внутреннего target; физические координаты не округлять. Проверить реальное отсутствие дрожания/швов, решение не считается доказанным документом.

Выбранные occluder groups скрывать целиком, если их геометрия перекрывает героя от камеры. Bounds — только broad phase; для арки/пустот подтвердить попадание в действительную поверхность, иначе пустой пролёт будет ошибочно скрываться. Проверять экранные точки ног/центра/головы спрайта: unproject каждую на near/far planes текущих матриц, луч параллелен view direction и ограничен глубиной соответствующей точки. Луч из точки camera к leader не использовать: вне центра кадра он не соответствует ортографической проекции. Настил, его борт/перила и перекрывающие стены могут входить в одну небольшую группу, открывающую участок нижнего пути; независимые опоры/соседний мост не скрывать целиком вместе с районом. При проходе сверху опорная поверхность под ногами не считается перекрытием (исключить конечную точку луча с малым epsilon); скрытие соседней стены не убирает опору из физики.

Привязка members к SurfaceMesh draw ranges создаётся из исходных map элементов при rebuild, не через изменчивые triangle indices. Blocker-only фильтр недостаточен: настил может быть floor slab или occupancy geometry. Использовать hysteresis: скрыть при пересечении, вернуть после 0,15 с без пересечения; состояние presentation-only, очищается при смене сцены/восстановлении. Коллизии, потолок, верхняя опора и доступность взаимодействий не меняются. Не рисовать героя поверх всего без depth. Спутников можно перекрывать — читаемость лидера и участка пути обязательна.

Правило опоры имеет приоритет над скрытием группы: настил, на котором сейчас стоит лидер, остаётся видимым. Стены/перила, способные закрыть героя на верхнем пути, авторить отдельной скрываемой группой; не объединять их с опорным настилом в неразделимый draw. Под мостом обе группы могут скрываться по собственным пересечениям. Исключение конечной точки луча само по себе не решает случай, когда голову закрывает другой member той же группы.

Вырез настила не оставляет висящие перила и верхние изображения: связанные декоративные части принадлежат его локальной группе; изображение спутника на скрытом верхнем участке временно скрывается вместе с ним, продолжая свой путь в симуляции. Спутник на видимом нижнем участке остаётся видимым. В E3 это правило распространяется на прикреплённые пропы и верхних NPC в пределах вырезаемого участка. Не скрывать всех акторов/геометрию с большей Y по всей карте. Визуальная проверка включает случай, когда лидер уже внизу, а спутник ещё проходит верхнюю часть маршрута.

Спутники используют историю полной 3D-траектории лидера с промежуточными точками по рампе/лестнице/поворотам. Не проводить прямую интерполяцию сквозь настил между разнесёнными точками; при разрыве (portal/recovery) очистить историю и поместить всех на проверенную опору лидера. В P1 нет самостоятельного выбора маршрута спутниками.

## Приёмочные сценарии и артефакты

1. Собрать `game-release`, запустить `rat-game` из build, затем извлечённый ZIP вне checkout с иным working directory. Обе сцены, PNG и шрифт загружаются. Без PNG/с malformed metadata — понятная ошибка; исходные карты/save не меняются.
2. Пройти двор обычным путём, попытаться пройти лаз стоя прямо и диагонально (отказ), пройти с Ctrl, отпустить под потолком (остался присевшим), выйти и встать. Измерить скорости и отсутствие прохода через боковую стену. Headless regression проверяет границы footprint и исключает tunneling при нескольких catch-up ticks.
3. Подойти к лестнице снизу и сверху, войти по E, пройти оба направления, безопасно выйти, повторить с Ctrl/зажатым E. Спутники не блокируют. Headless сценарий проверяет валидную опору после выхода.
4. По E перейти courtyard→sluice→courtyard десять раз; нет немедленного обратного переноса или потери карты. Инъекция ошибки загрузки target сохраняет scene/позицию. Сорваться с обозначенного края и восстановиться; восстановление после перехода остаётся в новой сцене.
5. Пауза во время движения/у портала/на лестнице, удержание Enter при resume, потеря фокуса: мир не движется в паузе, действие не протекает. Headless assertions по tick/позиции/scene.
6. Реальный renderer на 1280×720 и 1920×1080: герой перед/за стеной, в лазе, на лестнице/верхней площадке; PNG прозрачный, нет дрожания при движении, закрывающая стена скрывается устойчиво и возвращается. Отдельно поставить лидера вне центра кадра: действительно перекрывающая его стена скрывается, боковая стена без перекрытия остаётся видна, стена за глубиной лидера не скрывается. Сохранить screenshot/video и log с backend/adapter, frame times, commit и конфигурацией. Software/headless прогон не заменяет этот визуальный проход.
7. Пройти под мостом и по нему в обоих направлениях, остановиться в одинаковых XZ на разных Y. Нет snap наверх, провала сквозь настил, прохода в опору/борт или блокировки пустоты под мостом. Headless проверяет фактические высоты опоры/головы, стороны плиты, вход/выход рампы и recovery на выбранном ярусе. Ранее закрытые bridge/voxel regressions продолжают проходить; новая fixture проверяет игровые размеры тела, не переписывает прежний результат.
8. Вне центра кадра пройти под группой slab+стена: видны лидер и нижний путь, группа возвращается без мигания; на мосту настил виден, верхняя опора сохраняется всегда. Луч через пустоту арки не скрывает её ошибочно; несвязанная соседняя группа остаётся видна. Сохранить реальные кадры сверху/снизу и в движении. Спутники проходят ту же рампу и нижний путь без среза через настил; portal/recovery не оставляет их на прежней высоте.
9. Портал и вход лестницы, совпадающие в XZ с другим маршрутом, доступны только в своей области высоты и без разделяющей плиты; недопустимая цель не вытесняет допустимую ближайшую. Один E не активирует обе. Полные предметные взаимодействия сквозь этажи проверяются в P2, а не реализуются этой карточкой.

После реализации — полный существующий Release editor build, актуальный CTest (включая link isolation и новые headless сценарии), vault check; новые Python-тесты нужны только при изменении Python. Архивные 714/16 не являются новым результатом. Evidence в `docs/audits/2026-09-08-rat-expedition-traversal.md` (если фактическая дата другая — имя по дате проверки), тяжёлые снимки/ZIP в build artifacts с точными путями. Нет боя, квеста, persistent save, оплаченных ассетов, генератора уровней или универсального import framework.
