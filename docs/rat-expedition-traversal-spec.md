## Геометрия и данные полного P1

Двор `expedition_courtyard` примерно 16×12 units содержит обычный обход, ровный низкий лаз, лестницу к высоте 1,6, стену перед камерой, край recovery и портал. Водосброс `expedition_sluice` примерно 8×8 содержит свободный spawn вне обратного портала и безопасный путь. Размеры — параметры fixtures.

Предложения A4: одна единица — длина тела; скорости walk/crouch/climb 3/1,5/1 units/s; standing/crouched height 0,8/0,4, radius 0,2. Потолок лаза 0,6 над ровным полом. Отдельный мост: верх 1,6, толщина 0,2, низ 1,4; верхний подход по рампе, нижний путь под теми же XZ. Это высокий проход, не замена лаза. Опоры/перила не блокируют низ; настил — конечный объём, не ground column до верха. В одинаковых XZ существуют разные устойчивые Y: выбирать опору с учётом текущих ног/движения/clearance, не ближайшего этажа или одного 2D height lookup. Ступенчатый визуальный марш может иметь согласованный collider-пандус в E3.

Game JSON версии 1 использует устойчивые scene/geometry ids. Project manifest содержит start scene и словарь metadata paths. Полные scene metadata содержат именованные spawns (обязательный entry), portal 3D bounds ног/допуск Y и target scene/spawn, ladder нижний/верхний вход и безопасные выходы, low-passage floor/ceiling, recovery threshold (fixture −2), occluder groups с существующими уникальными members/деталями без двойного членства. P1.1 вводит только необходимые ему поля.

Все числа конечны, bounds min<max, floor<ceiling; пути относительные внутри Content без абсолютных/escaping путей. Проверить ссылки всех сцен до первого входа. Spawns/подходы стоят на устойчивой поверхности с полной standing clearance. Видимые объёмы согласованы с collision fixtures. Metadata не заменяют физический потолок. Новые форматы не называются совместимыми с legacy map/replay/save.

Контекст портала/лестницы сначала фильтруется по доступной высоте и твёрдой преграде, затем nearest/stable id. Цель другого уровня не вытесняет допустимую; один E не активирует две. P2 применит то же правило к предметам, без реализации предметов в P1.

## Тело, ввод и переходы

WASD относительно фиксированной камеры, E/Enter контекст, удержание Ctrl приседание, Escape пауза; свободные прыжок/вращение камеры отключены. Tick 1/120 с. Input содержит оси, crouch held и одноразовые interact/pause. Snapshot содержит scene id, координаты/стойку лидера, visual positions партии, режим/единственную подсказку; handles GPU не входят.

P1.2 меняет принятый объём тела до motor step. Стоя нельзя войти в лаз прямо/диагонально; присев можно. Вставание проверяет полный увеличенный объём/footprint, не один луч. Horizontal sweep/substeps, потолок и ladder exit учитывают фактическую высоту; catch-up не допускает tunneling. Нельзя отключать ceiling collision или лишь откатывать картинку. Под потолком после отпускания Ctrl остаться crouched с «Здесь нельзя встать»; после полного выхода автоматически встать.

Лестница захватывается новым E из доступного входа при standing clearance. Во время подъёма Ctrl игнорируется; WASD вверх/вниз, скорость 1. Оба выхода дают свободную устойчивую опору без blocker/пустоты; скорость walk/crouch восстанавливается. Наличие Stride character component не доказывает этот контекстный motor.

Portal подготавливает кандидата до замены активной сцены. Успех устанавливает target spawn, Standing, grounded/нулевую скорость и сбрасывает accumulator/pending input/trail/occlusion history. Spawn вне portal bounds; обратная активация требует отпускания и нового нажатия. Ошибка сохраняет прежнюю сцену/позицию и объясняет отказ. Recovery возвращает к последней standing-safe grounded не-climbing точке текущей сцены с теми же сбросами; после перехода такой точкой становится новый spawn. Верхняя соседняя поверхность не выбирается запасным spawn автоматически.

Пауза останавливает ticks, очищает accumulator/pending input; действие меню не поступает в мир. При resume held WASD может двигать, но E/Enter требует нового нажатия. Потеря фокуса ставит на паузу. Новые Core sequence tests проверяют эти правила; перенос C++ replay/checksum/schema и его debug интерфейсов не требуется. Межсценовые проверки принадлежат game session.

## Изображение и спутники

Временный оригинальный PNG atlas 64×192 содержит четыре направления × два кадра 32×48. Копия и источник находятся в game-owned Content/tools с credits. Реальная загрузка PNG обязательна: цветной quad не заменяет её. Три героя различаются tint, не имеют коллайдеров/самостоятельного pathfinding.

Камера фиксирована, ортографическая 3/4; foot anchor совпадает с телом, billboard смотрит на камеру. Point sampling, прозрачный фон и корректный depth относительно геометрии; `IgnoreDepth=true` запрещён. Alpha/premultiplication согласуются со Stride pipeline. 640×360 с integer nearest upscale 2×/3× — исходная A7 гипотеза полного P1, не обязательная архитектура P1.1. До завершения P1 проверить движение на обоих разрешениях; если нужен low-resolution compositor/snap, менять только представление, не округлять физику. Для иных окон — целый fit/letterbox, UI читается отдельно. Удачный статичный кадр не доказывает отсутствие дрожания.

Occlusion groups локально скрывают model entities/прикреплённые детали только в представлении. Bounds — broad phase; подтвердить действительное пересечение поверхности, чтобы пустота арки не скрывала группу. Для экранных ног/центра/головы использовать unproject near/far: параллельные ортографические лучи до глубины точки героя. Луч camera-position→leader вне центра кадра неверен. Стена за лидером, боковая/соседняя несвязанная группа остаются видимыми.

Скрыть при пересечении, вернуть после 0,15 с без него; очищать историю при portal/recovery. Коллизии, потолок, верхняя опора и контекст не меняются. Привязки стабильны по entities/geometry ids, не по случайным triangle indices. Настил под стоящим на нём лидером всегда видим. Его перекрывающие верхнего героя стены/перила авторятся отдельной группой: epsilon в конце луча не решает пересечение другого member той же группы.

Вырез нижнего пути не оставляет висящими перила/пропы и изображение спутника на скрытом верхнем участке. Его trail продолжается; нижний спутник остаётся видимым. Не скрывать всех акторов с большей Y на карте. В E3 правило распространяется на attached props/верхних NPC. Независимые опоры/соседний мост не исчезают вместе с районом.

Спутники повторяют полную 3D историю с промежуточными точками рампы/лестницы/углов; запрещена прямая интерполяция сквозь настил. При portal/recovery разорвать историю и поставить всех на проверенную опору лидера.

## Приёмка полного P1

1. Build/test/self-contained publish; извлечённый ZIP вне checkout и из другого cwd работает без editor/SDK/source/network. Обе сцены/PNG/используемый шрифт доступны; ошибки PNG/metadata читаемы. Старые карты/save не меняются.
2. Обычный путь, отказ лаза стоя прямо/диагонально, проход Ctrl, blocked stand и вставание после полного выхода; скорости, боковая стена, footprint края, catch-up tunneling.
3. Лестница снизу/сверху, оба направления/выхода; повтор с Ctrl/held E. Выход grounded, спутники не мешают.
4. Courtyard→sluice→courtyard десять раз без мгновенного возврата. Ошибка target сохраняет scene/позицию; recovery до/после перехода возвращает на нужный ярус текущей сцены.
5. Пауза при движении/у портала/на лестнице, Enter при resume, focus loss: ticks/позиция не меняются в паузе, действие не протекает.
6. Реальный GPU 1280×720 и 1920×1080: герой перед/за стеной, в лазе, на лестнице/верхней площадке, alpha/depth и движение без неприемлемого мерцания. Вне центра кадра проверить настоящую преграду, боковую стену и стену за глубиной лидера.
7. Мост сверху/снизу в обе стороны, остановка одинаковые XZ/разные Y; без snap, провала/прохода через настил, входа в опору или блокировки пустоты. Проверить грани плиты, голову/опору, рампу и recovery выбранного яруса новыми Stride tests.
8. Локальный slab+wall вырез открывает героя/нижний путь и возвращается устойчиво; верхний настил видим под лидером, физическая опора сохранена всегда. Пустота арки, соседняя группа, верхний/нижний спутники и trail/reset проверяются отдельными кадрами/проходом.
9. Portal/ladder при совпадении XZ другого уровня фильтруются высотой/преградой до nearest/id; один E не запускает две цели.

Evidence: `docs/audits/<actual-date>-stride-expedition-traversal.md`, тяжёлые PNG/ZIP/logs в `build/stride-game/` с точными путями, game commit, source SHA, package versions, backend/реальным adapter и результатами. Core assertions, GPU проход и ручная проверка различаются. Старые CTest не являются Stride tests. При закрытии этапа выполнить требуемую проектом Release-проверку редактора, отдельно обозначив сохранённый C++ baseline. Без боя/квеста/persistent save/MCP/универсального редактора/массового арта.
