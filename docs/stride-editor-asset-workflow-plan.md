## Результат и границы

Обновление порядка 2026-09-09: пользователь явно разрешил начать реализацию A1,
отложив оставшуюся ручную приёмку P1. Реализация/автоматическая приёмка P1 и оба
сообщённых исправления приняты; прежнее условие полностью закрытого P1 ниже
заменено этим решением. Ручной P1 не объявляется выполненным и остаётся в vault.

Пользователь открывает игровой проект в пересобранном Game Studio, размещает объекты, меняет свойства и ссылки на ресурсы, сохраняет сцену и запускает игру с этими изменениями. Та же авторская сцена компилируется в самостоятельный Windows ZIP. Видимая стена и её ограничение для Core меняются от одной правки, без второго ручного JSON.

Сейчас двор строится программно из `games/rat-expedition/Content/courtyard.json`; там же находятся PNG крысы, Noto Sans/OFL и credits. Проект Game Studio с редактируемой картой этим планированием не создан. Остальные категории ниже требуют будущих небольших собственных тестовых ресурсов. Сборка редактора и прежний startup smoke не доказывают авторинг ни одной из них.

План сохраняет закреплённый Stride `e2c786a45f69917bf233793f6a097b150e2fe264`, локальные пакеты `4.4.0-dev`, отдельный upstream checkout и игру в `games/rat-expedition/`. Точные форматы проекта, расширения, сериализуемые компоненты, редакторские свойства и точки asset compiler исполнитель проверяет по этому исходному baseline в первом срезе. Ниже — целевой контракт, а не заявление о проверенных API. Stable-пакеты, неподтверждённые плагины, MCP, патчи upstream и новый универсальный RPG-редактор не входят в план.

## Один авторский источник

Предлагается хранить native scene/prefab и другие редакторские asset definitions в игровом `Assets/`, импортируемые исходники — в `Resources/` с происхождением и лицензиями; точную структуру квалифицировать до миграции. Существующие пути остаются действующими до переключения проверенной сцены. Производные компилированные данные и кеши не являются авторскими файлами и не редактируются вручную.

Объект сцены получает устойчивый игровой id, назначение и нужные свойства: solid/декор, параметры объёма, spawn, точки/ссылки лестницы, а после P1.3 — переходы, безопасные точки и группы перекрытий. Идентичность не зависит от display name, позиции или пути файла. Дублирование prefab создаёт уникальные игровые ids экземпляра; переименование сохраняет идентичность, удаление оставляет проверяемую ошибку в ссылках. Формат id и сериализацию закрепить после квалификации native механизма.

Граница Stride → Core преобразует авторские данные в чистое валидированное представление. Core не получает Stride-типы и продолжает владеть FSM, feet Y, движением и контекстом. Для solid box одни свойства размеров/transform определяют и отображение, и Core volume; отдельная ручная копия bounds запрещена. Декоративная модель явно помечается как неколлизионная. У сложного визуального пропа допускается явно заданный collision proxy в том же prefab, но это видимая автору отдельная форма, а не автоматическое обещание точной mesh collision.

Для текущих конечных axis-aligned boxes поддерживаются конечная трансляция и положительные размеры по осям; rotation solid-объекта и влияющих родителей должна быть identity, scale — единичный. Размер меняется через свойства объёма с согласованным визуальным обновлением. Shear, отрицательный/нулевой scale и произвольное вращение solid не превращать молча в приблизительный AABB: отклонять с указанием объекта/свойства. Декоративные объекты могут иметь native transforms без изменения Core. Для фактически реализованных к началу A1 рамп/мостов P1.3 отдельно зафиксировать допустимые параметры и parent transforms; перенос не расширяет физический контракт ради удобства редактора.

Один этап извлечения/валидации авторских данных применяется при запуске из Game Studio и при обычной сборке. Конкретную compile/load границу выбрать в A1.1 и доказать на примере. Невалидный кандидат не заменяет рабочую сцену; startup завершается читаемой ошибкой, переход сохраняет прежнюю сцену по P1.3. Ошибка содержит asset, id/объект, свойство и причину. Generated JSON допустим только как автоматически получаемый артефакт, не второй источник. После миграции активного двора runtime не продолжает незаметно читать старый `courtyard.json` при ошибке authored asset.

## Покрытие ресурсов

Для каждой категории квалифицируются сохранение/повторное открытие и использование в игре/ZIP. Неиспользуемая категория получает явную отметку с причиной; обязательные отсутствующие категории проверяются одним собственным минимальным fixture, без производства полного набора арта или реализации боевой/UI/аудиосистемы.

| Категория | Авторский источник и работа в Game Studio | Внешняя работа и проверяемый пример |
| --- | --- | --- |
| Карты/сцены | Native scene: иерархия, размещение, свойства, ссылки; все игровые сцены, имеющиеся после P1 | Перенести двор и сцены P1.3; сохранить/переоткрыть, проверить переходы и совпадение коллизий |
| Prefab/повторяемые объекты | Состав, настройки, instances и ссылки на ресурсы | Собственный проп с двумя экземплярами; проверить обновление общего ресурса, различимые ids и сохранение локальной правки |
| Модели | Импорт, placement, привязка материалов; поддерживаемые форматы уточнить по pin | Геометрия/UV создаются во внешнем 3D-инструменте; один собственный mesh переимпортируется без потери корректных ссылок |
| Текстуры/материалы | Import settings, alpha/filter/color space, параметры и ссылки материала | Пиксели рисуются во внешнем инструменте; заменить собственную текстуру и проверить материал/прозрачность после rebuild |
| Спрайтовые листы и анимация | Atlas, кадры, pivot, последовательности/настройки воспроизведения через квалифицированный native путь | Сохранить нынешний rat PNG и видимый масштаб; редактирование пикселей внешнее. Проверить направление/кадры и depth; skeletal/model clips учитывать при появлении |
| Звук/музыка | Импорт, ссылки, параметры воспроизведения/громкости в пределах native свойств | Запись/синтез/монтаж внешние; один собственный короткий сигнал, воспроизведение в обычном запуске и ZIP без создания боевой аудиосистемы |
| UI и шрифты | UI asset/layout, свойства, ссылки шрифтов; фактические возможности подтвердить | Noto/OFL сохраняются; внешний рисунок и исходники шрифта не редактируются обещанно в Game Studio. Один экран с кириллицей и изменяемым элементом |
| VFX, если используются | Native effect/particle asset, ссылки, параметры и placement после квалификации | Собственный минимальный эффект при использовании этой категории; raw shader source редактируется как код вне property editor. Если в игре VFX нет, записать N/A, не строить систему эффектов |
| Игровые metadata | Сериализуемые свойства сцены/prefab: ids, volumes, spawn, лестницы, ссылки P1.3 | Код правил остаётся C#; инспектор редактирует данные, не заменяет FSM. Проверить ошибки и отражение изменения в Core |
| Импортируемые исходники и лицензии | Устойчивые относительные связи исходник → asset, реестр автора/лицензии/использования | Собственные исходники хранить в Git, notices/credits включать в ZIP; отсутствующий исходник при reimport и запрещённый внешний путь дают понятный отказ |

Game Studio отвечает за импорт, размещение и доступные ему свойства/ссылки. Редактирование mesh/UV, пикселей, аудиозаписи и произвольного исходного формата остаётся во внешних приложениях. Hot reload всех форматов, редактор анимационного графа и полноценное производство контента не обещаются.

## Ограниченные срезы реализации

| Срез | Работа | Доказательство перед продолжением |
| --- | --- | --- |
| A1.1 Квалификация проекта | Открываемый native game project/package в pinned Game Studio; минимальная собственная scene + custom metadata; определить compile/load, package references и source anchors | Реальное открытие GUI, изменение/сохранение/переоткрытие свойства, обычный запуск и compile того же asset из build wrapper. При несовместимости записать конкретный блокер, не подменять движок |
| A1.2 Карта и Core | Перенести двор, volumes, spawn и лестницу; stable ids, допустимые transforms и единая валидация; затем остальные фактические сцены/metadata полного P1 | Перемещение стены в редакторе меняет и вид, и столкновение без правки JSON; безопасные лестницы/переходы/верх-низ сохраняются, invalid edits отвергаются |
| A1.3 Библиотека ресурсов | По одному представительному ресурсу каждой обязательной категории; prefab instances, import/reimport и внешние исходники/лицензии | Сохранение/переоткрытие, rename/delete references, видимое/слышимое изменение в запуске; условные категории явно учтены |
| A1.4 Сборка и общая приёмка | Переключить normal launch/build на authored assets, убрать активную двойную конфигурацию; обновить README/диагностику/регрессии | Полный GUI цикл, независимое ревью, Release Game Studio, committed-head ZIP и проверка parity; фактические действия/пути/ограничения записаны |

Последовательность внутри одной будущей карточки уточняется исполнителем по результатам A1.1. Закрытый полный P1 — входная зависимость A1; A1 — предлагаемая зависимость P2 и обязательная основа до массового контента E3. Это план очереди, не разрешение начинать миграцию сейчас и не закрытие оставшегося P1.3.

## Приёмка и доказательства

После принятого A1 отдельный [пилот трёх обликов и ходьбы](stride-character-sprite-plan.md) использует квалифицированный native sprite workflow: сначала один герой, затем остальные два и проверка движения/партии. [Будущая карточка](../vault/production/tasks/feat-expedition-character-sprites.md) готовит персонажей к массовому арту E3; она не добавляет условий завершения A1 или зависимости P2. Представительный sprite fixture A1 остаётся ограниченной проверкой инструмента, а не производством всего набора персонажей.

1. В реальном пересобранном Game Studio открыть игру, карту и библиотеку. Разместить/сдвинуть стену, изменить свойство и ссылку ресурса, выполнить undo/redo, сохранить, закрыть и повторно открыть. Запустить обычную игру из редактора; история GUI и кадры/видео подтверждают действия, а не только наличие файлов.
2. На изменённой карте проверить прежнюю и новую позицию стены: старый участок проходим, новый блокирует полный объём; визуальная стена совпадает с Core. Отдельно проверить unsupported rotation/scale/parent transform, duplicate ids, spawn внутри стены, отсутствующую опору и преграду на capture/exit лестницы. Невалидная карта не запускается «как раньше» через старый JSON.
3. Переименовать и удалить используемый asset/объект: rename сохраняет корректные native ссылки и игровые ids либо выдаёт явную диагностированную несовместимость; удаление не оставляет скрыто используемую старую копию из cache. Восстановление/undo возвращает рабочую сцену. Проверить prefab instances, отсутствующий import source, reimport изменённого ресурса и ошибку повреждённого файла.
4. Для таблицы ресурсов записать конкретный fixture, GUI действие, сохранённый результат, обычный запуск и проверку пакета. Слышимость аудио не доказывается одним exit code; кириллица, sprite pivot/alpha и материал проверяются в реальном изображении. Native preview без исполнения в игре недостаточен.
5. Из committed game HEAD построить self-contained ZIP с теми же authored assets; распаковать вне checkout, запустить из другого cwd. Сравнить id/параметры валидированного мира и ресурсы с обычным запуском из Game Studio, приложить реальные 1280×720/1920×1080 кадры. Пакет не требует редактора, SDK, NuGet, source checkout или сети; отдельно подтвердить изоляцию от developer paths и раскрыть, была ли проверка на чистой машине.
6. Сохранить FSM, Ctrl/blocked stand, E/Enter edge/focus flush, подъём/спуск, feet Y, поведение полного P1, камеру 5.0/wheel и глубину upright героя. Адаптировать существующие Core/executable регрессии к новому загрузчику; переход на native assets не отменяет проверку отказов и packaged closure. Зафиксировать independent review, команды/exit codes, версии/commit, пути artifacts и ограничения ручных/автоматических проверок.
