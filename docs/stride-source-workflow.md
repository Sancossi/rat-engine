# Работа с исходниками Stride

Rat Expedition использует официальный [Stride](https://github.com/stride3d/stride).
Исходная основа закреплена в [engine.lock.json](../tools/stride/engine.lock.json):
`e2c786a45f69917bf233793f6a097b150e2fe264`, snapshot ветки `master` от 2026-09-08.
Это разрабатываемая версия 4.4, а не стабильный выпуск. Локальная сборка получила
версию `4.4.0-dev`; другой checkout может получить другой суффикс.

## Подготовка и сборка Windows x64

Закреплённый upstream требует Git LFS, .NET 10 и средства Windows C++ из Visual Studio 2026
(Windows SDK 10.0.22621 или новее, MSVC x64/x86). `global.json` задаёт SDK `10.0.100`
с `rollForward: latestMinor`; проверено с `10.0.300`. LLVM для `dotnet build` приходит
через upstream NuGet-зависимость. Первая подготовка требует доступа к GitHub/LFS/NuGet.
Android, iOS, ARM64 и VSIX для этого среза не нужны.

Из корня `rat-engine`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stride/bootstrap.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stride/build.ps1
```

Для другого расположения передать обеим командам `-CheckoutPath C:/work/stride`.
Bootstrap создаёт remote `upstream`, проверяет закреплённый объект, создаёт ветку
`rat/expedition-foundation` и получает LFS. Повторный запуск сохраняет текущий HEAD,
включая собственные коммиты поверх baseline. Существующий чужой каталог, неправильный
remote, другая ветка, отсутствующий предок или незакоммиченные файлы вызывают отказ.
Скрипт не выполняет reset, удаление каталогов или изменение глобальной конфигурации Git.
После прерванного первого клонирования частичная копия сохраняется: её следует осмотреть
и восстановить вручную либо выбрать новый каталог, а не удалять автоматически.

Build тоже требует чистое дерево на закреплённой локальной ветке: собственную доработку
перед воспроизводимой сборкой нужно закоммитить. Он проверяет LFS, вызывает только проект
редактора в `Release`, `Windows`, `Direct3D11`, `StrideNativeWindowsArm64Enabled=false`.
Указание ARM64=false существенно: первоначальная сборка автоматически включила ARM64,
но линкер не нашёл CRT-библиотеки этой архитектуры. Для требуемого x64 редактора патч
исходников не понадобился.

Результат:

```text
C:/5_gamedev/stride/sources/editor/Stride.GameStudio/bin/Release/net10.0-windows/Stride.GameStudio.exe
```

Логи лежат в игнорируемом `stride/logs/rat-foundation/<timestamp>/`: `build.log`,
`build.binlog`, `result.json` с реальным HEAD, SDK, аргументами, exit code, путём
редактора и его версией. Нулевой код принимается только при наличии executable.
Это проверка сборки; редактирование сцены и работа игры требуют отдельной проверки.

## Свои изменения и обновления

1. Сначала воспроизвести конкретную проблему на закреплённой основе. Прикладные скрипты,
   ассеты, MCP-мост игры и правила RPG размещать в проекте игры; править движок, когда
   существующего API действительно недостаточно.
2. Делать отдельные небольшие коммиты над upstream, с воспроизведением и проверкой.
   Текущая интеграционная ветка — `rat/expedition-foundation`. Для работы на другой
   ветке осознанно изменить `localBranch` в lock и зафиксировать это в проекте:
   wrappers специально откажут на случайно выбранной ветке.
3. Перед обновлением сохранить рабочую ветку, выполнить `git fetch upstream`, выбрать
   конкретный новый SHA и изучить изменения API/форматов. Интегрировать upstream через
   merge в отдельной рабочей ветке с сохранением собственных коммитов, разрешить конфликты,
   обновить lock, затем проверить сборку и игровые сценарии. Bootstrap сам не обновляет HEAD.
4. Вносить новый baseline и проверочные свидетельства согласованным коммитом проекта.
   Если upstream принял наш патч, удалить дублирование при следующей интеграции.

Собственный fork — [Sancossi/stride](https://github.com/Sancossi/stride), remote `origin`;
официальный репозиторий остаётся `upstream`. В lock `upstreamCommit` сохраняет исходную
основу, а `engineCommit` фиксирует точную интеграцию с нашими патчами. Первый патч
`88301e861149c48c8b408aac3030b190332d7f97` добавляет native session save/close lifecycle
для MCP; [контракт и квалификация](audits/2026-09-09-stride-editor-mcp.md).

По указанию пользователя от 2026-09-09 MCP, адаптер и дальнейшие проверенные доработки
инструментов редактора вместе с документацией сохраняются отдельными коммитами и
публикуются в существующем репозитории `sancossi/rat-engine` после review и проверок.
Если понадобятся изменения непосредственно исходников Stride, они сохраняются
отдельными коммитами в собственном fork движка; проект фиксирует соответствующий SHA
в engine lock, а коммиты и документация обеих сторон содержат взаимные ссылки.
Исходники движка не копируются в репозиторий игры. Первый MCP bridge работал без
патча; независимый review выявил отсутствие полного native Save/Close state,
поэтому интеграция теперь включает указанный минимальный патч.

Новый bootstrap клонирует upstream, получает точный `engineCommit` из fork и создаёт
локальную ветку на этом объекте; LFS также загружается из fork для собственной
интеграции. Checkout старого baseline сохраняется без автоматического переключения.
После публикации ветки и проверки чистого дерева обновить такой checkout явно:

```powershell
git -C C:/5_gamedev/stride remote add origin https://github.com/Sancossi/stride.git
git -C C:/5_gamedev/stride fetch origin rat/expedition-foundation
git -C C:/5_gamedev/stride merge --ff-only 88301e861149c48c8b408aac3030b190332d7f97
```

Если `origin` уже существует, сначала проверить его URL, не добавлять повторно.
`merge --ff-only` откажет при несовместимой истории, сохранив собственные коммиты.
Не выбирать плавающий tip fork/master вместо lock. Зафиксированный игровой NuGet
cohort остаётся прежним: editor-only patch не разрешает молча менять game locks.

## Подключение игры и собственные выпуски

Upstream автоматически формирует пакеты в `stride/bin/packages` при обычной сборке.
Проект игры ссылается на проверенный локальный feed через собственный
`NuGet.Config` и закрепляет одинаковую точную версию всех first-party `Stride.*` зависимостей.
Сборка только редактора не гарантирует готовность всех вариантов пакетов для произвольной
игры: проверить полный dependency closure при создании проекта.

Для частой разработки движка upstream предлагает dev-redirect пакеты:
`dotnet run build/GenerateDevPackages.cs`. Это отдельный режим со ссылками на локальный
checkout, а не переносимый выпуск. `dotnet msbuild build/install-gamestudio.targets -t:Deploy`
размещает closure в локальном NuGet cache; эта команда меняет установленные пакеты и не
запускается автоматически нашими wrappers. Не очищать глобальный NuGet cache для обычной
пересборки. Подробности и ограничения: [закреплённое руководство сборки](https://github.com/stride3d/stride/blob/e2c786a45f69917bf233793f6a097b150e2fe264/docs/build/README.md).

Версии upstream определяются `sources/shared/SharedAssemblyInfo.cs` и генерируемым overlay.
Локальный ledger `%LocalAppData%/stride/worktree-ids.txt` назначает checkout суффикс
`dev`, `dev2` и т. д. Для собственного воспроизводимого выпуска нужны отдельный feed,
отличимая версия (например, prerelease-суффикс `rat.1`), точный Git SHA, SDK и параметры
сборки в manifest. Не переиздавать другой бинарный состав под той же версией или выдавать
сборку за официальный Stride. Перед упаковкой проверить фактически сгенерированные
версии и closure, поскольку release и dev paths upstream различаются. Изменение формата
ассетов требует числового повышения версии: один суффикс не разделяет пути upgrade.
См. [закреплённое руководство версий](https://github.com/stride3d/stride/blob/e2c786a45f69917bf233793f6a097b150e2fe264/docs/build/versioning.md).

Собственные сборки сохраняют `LICENSE.md` (MIT), `THIRD PARTY.md` и notices фактически
поставляемых сторонних компонентов. MIT разрешает изменение и распространение при
соблюдении условий уведомлений; отдельные зависимости имеют собственные условия.
GameStudio.csproj уже копирует основные notices в output; при собственном packaging
нужно сохранить их и проверить состав пакета. Текущий срез не создаёт публичный выпуск.

## Игровые срезы

Архитектура и контракт P1 адаптированы к Stride/C#. Текущая ортографическая сцена
содержит 2D персонажа, стены, низкий лаз и лестницу; [README игры](../games/rat-expedition/README.md)
описывает управление, Core-сценарии, самостоятельный Windows export и проверку ZIP.
Оставшиеся срезы P1 и их статус ведутся в vault. MCP подключается отдельной задачей
по [исследованию](stride-mcp-integration-research.md).
Установка AkerMCP и совместимость с этим snapshot пока не проверены.
