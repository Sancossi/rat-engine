# Три облика и ходьба Rat Expedition

Дата: 2026-09-09. Основание — пользовательский лист с тремя персонажами и направленными позами. [Запрос](../vault/production/tasks/design-expedition-character-sprites.md), [сохранённые наблюдения](../vault/game/expedition/rat-expedition-character-reference.md), [будущая реализация](../vault/production/tasks/feat-expedition-character-sprites.md), [A7](../vault/game/expedition/rat-expedition-art-audio.md). Это план; новые изображения, импорт и runtime сейчас не создаются. Статусы остаются только в vault.

## Замысел и открытые решения

Партия получает три отдельных игровых облика с собственными кадрами, а не три tint одного PNG. В листе различимы светлый узкий персонаж в фиолетовом, более широкий коричневый образ и тёмный образ с капюшоном. Визуально каждый представлен четырьмя направлениями и тремя позами на направление. Имена, пол и роли из одежды не выводятся: канонических героев задают GDD/нарратив. Привязку облика к постоянному id героя записать в пилоте.

Рабочее допущение — лист служит референсом; прямой импорт точного изображения остаётся открытым решением. Оригинальный файл, его pixel grid и условия использования пока не установлены. Это не препятствует плану: при будущем импорте понадобится исходник достаточного качества и обычная запись происхождения/изменений в credits. Не объявлять масштабированную картинку готовым atlas или автоматически пригодным экспортом.

Три наблюдаемые позы не доказывают правильный walk loop. Проверить в preview гипотезу «контакт одной ноги → промежуточная поза → контакт другой → промежуточная»; повтор промежуточного кадра не превращает три уникальных рисунка в четыре. Если рисунки задают иной порядок, выбрать по фактическому движению. Idle может временно держать подходящую позу. A7 предлагает walk 4 и idle 2: пилот явно фиксирует либо ограниченный трёхпозный вариант, либо недостающие рисунки. Бюджет полного фрагмента и GDD молча не меняются.

## Подготовка и native источник

Сначала подготовить одного героя. Уточнить реальные границы рисунков и направления; выбрать общий canvas для трёх силуэтов и постоянный foot pivot. 32×48 — прежняя гипотеза, не размер, доказанный вложением. Сохранить редактируемый исходник, нетронутый оригинал и alpha-экспорт. Не делать массовый resize до сцены: проверить хвост, края одежды, голову и последовательность контакта ног. Фон отделять по маске/связной внешней области с проверкой краёв; глобальный white color key повреждает светлую шерсть. Исключить белые ореолы и случайную полупрозрачность пикселей.

После принятого [A1](stride-editor-asset-workflow-plan.md) импортировать PNG/native sprite asset, задать regions, pivot, frame order, clip identifiers и cadence тем квалифицированным механизмом Game Studio, который использует игра. Точные API не считаются проверенными этим планом. Native definitions — один авторский источник для editor launch и ZIP; generated runtime metadata допустимы, второй ручной JSON atlas запрещён. Пиксели правятся во внешнем инструменте, Game Studio отвечает за импорт/доступные свойства/preview. Каждому герою нужен устойчивый skin/asset id и отдельная привязка кадров; имя файла или цвет tint не заменяют идентичность.

Размер тела сохраняется: radius .2, standing/crouched height .8/.4, камера 5.0 и zoom 4.5–7. Широкая одежда не расширяет collider автоматически. На пилоте подобрать canvas/pivot/видимый масштаб без произвольного растягивания рисунка, затем проверить каждый силуэт у стены, под потолком и на лестнице. Если форма не помещается в принятую подачу, зафиксировать необходимую правку арта/масштаба до тиражирования, сохраняя физический контракт.

## Анимация поверх существующей FSM

Физическая FSM остаётся владельцем Standing/Crouched/Climbing/Falling; новые физические Idle/Walk для этой работы не нужны. Представление выбирает clip по состоянию и фактическому перемещению, а не только удержанным клавишам. В Grounded движение вдоль выполненного пути задаёт walk cadence; без перемещения — idle/удержание последнего направления. Упор в стену не воспроизводит бесконечную ходьбу, скольжение поворачивает по действительному движению. Переходы четырёх направлений проверяются на диагоналях и малом числовом шуме. Частоту/дистанцию цикла подобрать на пилоте, не привязывать к render-frame counter. Paused замораживает и фазу, и выбор кадра.

Текущий `PartyTrail` хранит только Position/Stance/Mode; Facing/Phase/skin id в нём нет. Нынешние спрайты используют один 64×192 atlas, 2×4 кадра 32×48 и `frames/12`. Будущая реализация расширяет состояние/историю представления, чтобы каждый спутник имел свой skin, историческое направление, стойку и непрерывный прогресс цикла на своём участке полного 3D пути. Он не копирует текущие клавиши или кадр лидера. Смена стойки не переписывает входящий сегмент истории. Portal/recovery сбрасывают путь и фазу по явному правилу с сохранением личности героя; pause не продвигает историю.

На листе не подтверждены crouch/climb/fall. Для пилота отдельно показать временные fallback: удержанная подходящая поза для остановки/падения, проверенный кадр для лестницы; для crouch — согласованный временный вариант, проходящий проверку высоты и силуэта. Сжатие длинного пальто не считается готовой анимацией. Перед production принять dedicated кадры либо явно утвердить качественный fallback на реальном маршруте. Attack/combat clips и новые боевые состояния сюда не входят.

## Ограниченные шаги и приёмка

1. **Пилот одного героя:** оригинал/референс, canvas, alpha, pivot, отображение направлений, порядок трёх поз, соответствие A7 и стоимость подготовки. Показать неподвижный кадр и короткую ходьбу; после результата уточнить формат остальных двух.
2. **Native импорт:** открыть asset в rebuilt Game Studio, изменить pivot/clip, preview, undo/redo, save/reopen; затем изменить исходник внешне и reimport. Rename/delete/missing reference дают корректные ссылки или понятную ошибку, не старый кадр из cache.
3. **Движение и партия:** actual-displacement cadence, last facing, пауза, wall stop/slide, ramp/ladder/crouch/fall fallback, исторические poses спутников и reset. Проверить разный render cadence/catch-up наблюдаемыми последовательностями.
4. **Остальные два облика:** отдельные skins/направления/кадры по принятому шаблону. Проверить асимметрию одежды до зеркалирования, общий pivot без скачков и три узнаваемых силуэта в игровом масштабе.
5. **Доставка:** editor launch и извлечённый committed ZIP используют те же authored assets, regions/pivots/clips. Реальные 720p/1080p кадры и короткий проход показывают альфу, контакт ног, depth перед/за стеной, верх/низ моста и спутников. Повреждённый atlas, неверный region/pivot и отсутствующий clip диагностируются. Записать ручные замечания о ритме/читаемости, Core/executable регрессии, происхождение и время работы; не подменять визуальную приёмку exit code.

Пилот/набор — отдельная ограниченная квалификация **после A1, до массового арта E3**. Он не блокирует завершение самого A1 и не добавляет зависимость P2. E3 по-прежнему начинается после P7 и A1; цена/качество этого набора уточняют его производство. Реализация пока вне спринта.
