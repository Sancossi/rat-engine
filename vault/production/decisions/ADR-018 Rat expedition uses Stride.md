# ADR-018 — Rat Expedition использует Stride

## Context

Пользователь 2026-09-08 прямо выбрал движок: «Давай выберем Stride и изучим как можно реализовать к нему MCP и прочие вещи». Это новое решение после [[ADR-017 Rat expedition uses rat-engine]] и исследования [[research-open-engine-foundation]]. Автор выбора — пользователь bogor; техническую фиксацию подготовил Codex.

## Decision

Выбрать **Stride / C#** для будущей реализации Rat Expedition. Это решение заменяет ADR-017 в части игровой основы. Замысел и требования [[GDD]] сохраняются; прежняя C++-архитектура становится исторической и не служит контрактом новых игровых срезов.

Первоначальное решение не закрепляло версию Stride, SDK .NET и реализацию MCP. Последующее указание пользователя 2026-09-08 — перейти на официальный `stride3d/stride` с возможностью собственных сборок и доработок — уточняет исходную основу: [engine.lock.json](../../../tools/stride/engine.lock.json) закрепляет SHA `e2c786a45f69917bf233793f6a097b150e2fe264`, development snapshot 4.4; проверенная SDK .NET — 10.0.300. Отдельный checkout и порядок патчей описаны в [workflow](../../../docs/stride-source-workflow.md). Собственные изменения движка вносятся по конкретной необходимости, отдельными коммитами над upstream; локальный переход не означает публикацию fork или релиза.

[Исследование интеграции](../../../docs/stride-mcp-integration-research.md) предлагает проверить AkerMCP как адаптер Game Studio и отдельный мост диагностики работающей игры. Ни установка AkerMCP, ни его совместимость, ни готовность игрового управления пока не подтверждены запуском.

## Consequences

Первый технический шаг — [[feat-stride-source-foundation]]: локальная исходная основа и Release-сборка Game Studio. Следом — адаптация P1 и ограниченная проверка спрайтов в 3D, тестов и самостоятельной Windows-сборки игры; MCP подключается после готовности этого пути. Эти проверки уточняют реализацию уже выбранного Stride; повторное согласование выбора движка не требуется.

До игровой реализации следует адаптировать архитектуру и P1 к Stride через существующую [[expedition-prototype-traversal]]. Старые исходники, незавершённые изменения, карты и история rat-engine сохраняются; автоматического переноса кода и форматов нет. Сценарии приёмки можно переиспользовать как требования, но результаты C++-тестов не доказывают работу новой игры.

## Уточнение 2026-09-09 — завершение C++-итерации

Пользователь утвердил удаление прежнего C++-движка, редактора, ресурсов и сборочной инфраструктуры из рабочего дерева после перехода на Stride/C#. Это заменяет прежнее требование сохранять старые исходники и карты рядом с новой игрой. История Git не переписывается: последний снимок до очистки — `60fdc55f19889304fc29957fd2124624077aefcd`; документация и источник восстановления перечислены в [архиве C++](../../../docs/archive/cpp/README.md). Карточки, решения и закрытые спринты сохраняют историю. Ресурсы текущей игры, их авторство/лицензии, самостоятельный checkout Stride и нужный ему native toolchain сохраняются.
